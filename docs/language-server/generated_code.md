# generated_code.ts：生成 API 的静态建模

源码：[language-server/src/generated_code.ts](../../language-server/src/generated_code.ts)。由 `PostProcessModuleTypes` 调用 `ProcessScriptTypeGeneratedCode`。

## 生成的是什么

只生成内存中的 DBMethod/DBProperty/DBNamespace，补齐 Unreal 在运行时提供、脚本源码里看不到的 API。**不生成文件、不编译函数、不改变引擎绑定。**

| 类型/条件 | 典型建模 |
| --- | --- |
| UObject 类 | 类同名 namespace 的 StaticClass（受引擎禁用/弃用设置影响） |
| UActorComponent | Get / GetOrCreate / Create |
| AActor | Spawn（受 actor generics 设置影响） |
| USubsystem | Get；LocalPlayer 子类有参数重载 |
| delegate/event | IsBound、Clear、Execute/ExecuteIfBound 或 Broadcast/AddUFunction 等 |
| Haze 配置开启 | ComposableSettings、EffectEventHandler 特有 API |

`AddGlobalFunction`、`AddMethod`、`AddProperty` 写入 `isAutoGenerated`、模块与来源偏移；全局合成符号还要进入 `asmodule.globalSymbols`，保证模块清理时可移除。

## 项目配置扩展

根清单 `UnrealAngelscript.projectCodeGeneration` 支持配置生成器。以下是**假设项目引擎已经提供 Resolve API**时的编辑器建模示例：

```json
{
  "UnrealAngelscript.projectCodeGeneration.enable": true,
  "UnrealAngelscript.projectCodeGeneration.generators": [
    {
      "derivedFrom": "UObject",
      "staticFunctions": [
        {
          "name": "Resolve",
          "returnType": "{class}",
          "args": [{ "type": "UObject", "name": "Context" }]
        }
      ]
    }
  ]
}
```

得到如 `UMyType::Resolve(Context)` 的静态模型，而非真正实现。`staticFunctions` / `memberFunctions` 支持 `{class}`；`staticAccessors` / `memberAccessors` 遍历脚本属性，还支持 `{propType}`、`{propName}` 和属性类型 `derivedFrom` 筛选。成员函数可指定 const/property。

**当前项目生成器入口只在非 struct、非 enum 的类分支运行**，尽管配置描述提到 class/struct，不能据此承诺 struct 已支持。delegate/event 走其专门分支。

## 修改代码时

1. 在正确继承分支或 `ApplyProjectGeneratedCode` 扩展，避免给所有类型暴露项目特定成员。
2. 设置返回值、args、const/property、documentation 等模型字段，保持引擎签名一致。
3. 若生成方法关联源码属性/函数，评估 `auxiliarySymbols`；引用查找与重命名支持范围并不完全相同。
4. 保证重复解析不重复累积；移除类型时合成 namespace 和成员一起清理。
5. 配置更新当前只改 settings，未强制失效已后处理模块；验证时重新打开/编辑相关文件或重启语言服务，正式实现应补足失效机制。

测试：补全/签名/hover、返回类型链式访问、禁止直接 rename 自动生成符号、修改配置及类型后不残留旧 API。相关：[database](database.md)、[references](references.md)。
